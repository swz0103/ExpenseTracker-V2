# 持久安全備份限定原型

對應[資料演進契約](data-evolution-contract.md)的來源預檢與備份步驟。此原型只接受已驗證的 Ledger schema 3 世代，不執行 schema 升級，也不宣稱完成 EVOL-01～08。

## 實際行為

[createSafetyBackup](../prototypes/ledger_generation/lib/safety_backup.dart) 在來源世代生命週期鎖內，驗證來源格式／身份及完整帳務 snapshot，再建立現有加密 envelope。輸出目錄由可信 App composition 提供，必須已存在、為 App 自有目錄且在 generation 目錄之外；檔名由 backup UUID 導出。

新檔採 exclusive create，已有檔案、目錄或 link 一律不覆寫。flush 並關閉後重讀實際檔案，核對輸出內容，再分別以密碼和此次產生的救援 key 解鎖，確認兩者均精確還原完整 snapshot，才回傳成功及來源世代身份。鎖涵蓋驗證完成，避免中間插入帳務寫入。

未知來源 schema 在任何新備份寫入前拒絕；取消只在等待鎖階段生效。儲存或驗證失敗保留既有／部分輸出與來源資料，不自動刪檔、重新覆寫或換 key。相同 backup ID 再次執行仍拒絕已存在的輸出，沒有承諾跨程序備份操作的成功去重；完整升級 receipt 仍待後續實作。回傳 source 的 fingerprint 仍是原安裝輸入摘要，不能拿它當作後續帳務更新後的備份摘要；未來升級紀錄須另外核對實際備份內容。

## 錯誤與秘密

目的地、讀回驗證、儲存錯誤以去敏型別回傳；底層檔案路徑不出現在錯誤文字。來源世代或鎖失敗仍沿用 GenerationUnavailable。已知備份失敗在鎖正常釋放後回傳，避免被通用世代保護誤標為需要復原資料庫。

回傳的救援 key 是這一份新備份的憑證，未寫入正式磁碟或日誌。呼叫者必須有正確的呈現／安全保存流程；本原型沒有解決正式 BackupProfile 的憑證延續。測試寫到暫存目錄的憑證只用於合成 fixture 的獨立程序驗證，不能用於真實帳本。

## 驗證與限制

13 項新案例涵蓋：未知來源不改檔、還原後新增帳務也納入備份、兩種憑證讀回、各自的乾淨子程序還原、既有輸出保留、保存後竄改、儲存錯誤去敏、缺失／錯誤目錄、等待取消、讀回前維持排他權及無效密碼。33 項既有 Ledger 世代案例與靜態分析通過。

第一輪測試發現通用協調器會把備份錯誤轉成 recoveryRequired，已修正並重測。新增版本拒絕測試曾與同套件回歸同時執行，Windows 原生 DLL 被占用；改為回歸結束後單獨執行即通過。後續同一套件的 native 測試必須循序執行。

這是 Windows host 證據，未接 Android UI 或自動升級。檔案 flush 不等於斷電耐久性；exclusive create 後的檔案存取依賴 App 私有目錄與合作式協調，未聲稱能抵擋具有相同目錄寫入權的惡意程序。舊版來源 reader、真正升級前來源轉換、升級 receipt、保留清理、空間預估及真實磁碟滿仍待完成。
