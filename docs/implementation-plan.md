## 已確認的交付方向

- **1A**：消費為主要口徑，分期應繳／付款安排分開；退款在退款期記減項並追溯原消費，還款不重複列消費。
- **2A**：首個可用版本就有備份密碼、文字救援金鑰及兩條解鎖路徑；完整輪替、QR 與定期健康檢查延後。
- **3A**：先交付日常記帳，再補預算／定期交易／提醒與信用卡，最後接投資；所有 rc1 CORE 都仍需完成。
- **D-001／D-002**：採 A＋，按業務拆本機套件，內部有必要可以再拆。新功能沿公開接口接入，不能越界操作別人的私有資料。

本計畫把工作分為五階段、三個使用者可用里程碑。階段內逐功能完成；技術細節由助手收斂，不要求使用者逐張工作單核准。真正影響財務語意、安全、外部費用或範圍的變更，集中說明後再決定。

## 階段 0｜完成可實作的架構規格

**目的**：把現在的方向變成可據以實作的契約，先避免模組、資料與例外流程互相矛盾。此階段是設計文件工作。

1. 完成主模組清單、公開接口、允許依賴與資料主責；畫出實際依賴圖，確認無循環。確定必要的內部拆分，不預建全部未來套件。
2. 完成核心資料模型：帳戶、transaction／legs、分類關聯、charge、revision／reversal、operation ID、Workspace／Audit。預留信用卡與投資的來源關聯，細節資料仍歸對應業務。
3. 完成財務規則與具體例子：期初餘額、同幣／跨幣轉帳、費用、拆分尾差、部分退款、跨月退款、更正、重複提交、分期總額與付款不重複認列。
4. 定義版本與恢復契約：各模組 schema、整體 migration manifest、backup manifest、密碼／文字救援金鑰、舊版本資料與停用模組的處理。
5. 把 ADR-01～ADR-08 分成「文件可決議」與「需實測」兩類，為每個實測項列輸入、預期結果及失敗處置。這是技術工作清單，不新增八組使用者問題。

**輸出**：架構規格、資料模型、接口／錯誤、代表案例、風險及驗證清單。每項可追溯 RC／FV，不把資料模型圖當成已存在的資料表。

**通過條件**：日常記帳、信用卡買入／繳款及股票買入三條代表流程都能在模型中說清楚；沒有直接改餘額或跨模組私有表的捷徑。關鍵技術未知事項已列清楚，但還不能宣稱整體 Freeze。

## 階段 1｜驗證地基，再建立正式開發基線

**前置**：相關階段 0 規格可審查；依使用者後續開始授權，已建立[工程契約](foundation-contracts.md)與[驗收案例](foundation-acceptance.md)，可先執行限定原型解決技術未知事項。結果與尚未通過的 gate 見[驗證紀錄](foundation-validation.md)，不據此宣稱全部階段 0／1 完成。

1. **技術相容性**：依當時官方資料確認 Flutter／Dart、Drift／SQLite 加密、Decimal、UUID、平台 secure storage 與建置流程；實測後鎖定版本，不照舊文件猜套件 API。
2. **最短真實資料路徑**：以測試資料完成「帳戶 → 一筆收入／支出 → 關閉重開 → 餘額重建」。原型只驗證必要契約，不預先做完整產品畫面。
3. **跨套件原子提交**：用兩個參與模組保存同一操作，注入提交前失敗及提交後回覆遺失，驗證全部回滾或只成功一次；確認實際使用同一 SQLite transaction。
4. **安全與可攜還原**：本機資料加密、最小 envelope、密碼與文字救援金鑰各自還原；在乾淨環境驗證，不能只在仍持有原裝置密鑰的環境測試。
5. **Migration／版本**：以舊版本 fixture 升級，模擬中斷、空間不足與不相容備份，確認不覆寫成半套正式資料。
6. **供應商可行性**：檢查雲端備份、FX 與行情來源的官方契約、適用市場、權限及成本；選定 adapter 路線。實際完整整合依後續批次進行，不能將「有接口」標為已支援。需要付費或新增外部承諾時另行說明。

**輸出**：關鍵風險的實測結果、版本選擇、已結案 ADR，以及可供 Freeze 的架構基線。未通過的項目先修正規格與重測，不帶著假成功往後做。

**專案與基線**：依後續指示，先建立私人 repository 保存文件並走分支／PR 流程；通過架構 gate 後再標定正式 baseline commit 與 exact SHA，接續當期所需正式套件、CI 及功能分支。初始文件 commit 不等於 Architecture Freeze。建立狀態以[前置準備紀錄](development-readiness.md)及實際遠端結果為準。

原型若轉入正式程式，必須按正式品質要求整理與驗證；原型通過不能取代首批功能驗收。

## 階段 2｜M1：可開始日常使用的記帳版本

**前置**：已建立正式基線，基礎風險驗證通過。依下列順序完成小而完整的功能；資料層、Domain、必要畫面及驗證一同交付，不先寫完整後端再一次補全部 UI。

### M1-01｜帳戶、期初餘額與最小記帳路徑

先建立一般現金／銀行帳戶、幣別、期初餘額，接上一筆收入與支出；提供最小交易列表與明細。正式 DB 加密、App 鎖定、Audit、operation ID 與基本備份還原隨此路徑接入。初期用測試資料展示，尚未達 M1 gate 前不作為日常資料保存版本。

**驗收**：期初餘額不列收入；重啟後餘額可重建；重複送出不新增第二筆；錯誤寫入回滾。信用卡／投資專用入口尚未開放，不以一般帳戶流程冒充完整支援。

### M1-02｜分類、Tag、Merchant 與日常錄入

完成雙層分類、標籤、商家及基本 alias；以公開 ID 接入交易。整理快速新增、完整表單、草稿、錯誤／空狀態、隱私遮罩與基本無障礙；使用既定簡潔導航。

**驗收**：新增與修改使用同一套 Domain 驗證；商家合併／分類封存不破壞歷史引用，不把非必要個資寫進診斷紀錄。未開放模組不出現失效入口。

### M1-03｜轉帳、多幣別與結構化費用

先完成同幣轉帳，再擴至跨幣及明確費用；保存實際原幣數字與已確認匯率。M1 可先由使用者確認實際匯率，不能用虛構行情或缺值當 0。自動歷史 FX 與市場 provider 整合納入後批。

**驗收**：兩邊一起成功或回滾；轉帳本金不算消費；費用獨立可追查；不同幣別不得裸加；尾差符合已定規格。

2026-09-28 進度：[同幣轉帳與來源手續費](same-currency-transfers.md)及[跨幣實際雙本金](cross-currency-transfers.md)已接入草稿、雙帳戶保存／讀取、實際比例 context、版本升級與主機驗證。外部 FX provider、其餘費用組合及基準幣報表依後批保留；本機結果不取代 M1 gate 或實機驗收。接續 M1-04 多分類拆分。

### M1-04｜拆分、退款、更正與刪除規則

完成 split、部分／全額退款、revision、reversal、tombstone 及 Activity Timeline。一般改字與財務意義變更走適當路徑，不覆寫需保留的歷史。

**驗收**：split 加總正確；不能超額退款；退款在退款期反映並追溯原交易；更正前後的正式餘額與有效版本一致；涉及後續依賴時不能以刪除繞過檢查。

2026-09-28 進度：[多分類拆分](split-entry-drafts.md)的輸入、精確合計、凍結草稿、重試、複製與隱私明細已通過主機驗證；後續[平均／百分比／固定比例](split-allocation-assist.md)補齊 FV-016 基本分配與明確確認、尾差及鎖定檢查。退款、revision／reversal／tombstone 與活動歷史仍待後批，未宣稱 M1-04 或 M1 gate 全部完成。

2026-09-28 退款接續：[部分／全額退款](refunds.md)已完成主機範圍的原支出／分類限額、同幣與跨幣實收、原歸屬追溯、草稿與重試、schema 9 → 10、還原及簡潔入口；完整結果見退款證據。更正、撤銷、刪除、活動歷史及實機 gate 仍待完成，M1-04 不標全數完成。

2026-09-28 活動接續：[交易活動查閱](transaction-activity.md)完成原支出與退款關聯、記錄時間分頁及隱私；沿用既有 audit，可從雙路乾淨還原重建。一般編輯 revision、正式 reversal、tombstone 及完整活動歷史仍待後批；M1-04 尚未全部完成。

### M1-05｜搜尋、首頁與基本報表

提供帳戶／分類／商家／Tag／期間等已定的基本 AND 篩選、最近交易、消費為主的首頁、月收支、分類與資產摘要。建立實際需要的少量 projection，其他走讀取契約與索引查詢。

**驗收**：首頁／分類報表可追查至明細；不雙算轉帳與期初餘額；剛提交後餘額正確；過期報表顯示狀態；刪除衍生投影後可重建。無估值時明示缺值，不能假裝完整淨資產。

### M1-06｜CSV／JSON 與來源去重

完成自有格式匯出、匯入驗證、預覽與提交；匯入呼叫已完成的業務流程。失敗整批回滾或依事先定義的批次策略明示結果，不留下使用者無法辨認的部分成功。

**驗收**：至少一組真實 fixture round-trip、重複匯入不重複入帳、錯誤幣別／日期／引用可定位；清楚區分一般匯出與完整可還原備份。

### M1-07｜完整首批保護與日常試用發布

把前面每個新增模組的權威資料、revision、Audit 與必要去重資訊納入版本化備份。完成備份密碼、文字救援金鑰、保存引導、兩條路徑的實際還原與受控替換；App PIN／biometrics／自動鎖定、migration、安全模式與當期畫面隱私行為一併驗收。

**M1 gate**：從全新安裝建立帳戶、連續記帳、轉帳、拆分／退款、更正、搜尋報表、CSV／JSON 到加密備份；另在乾淨環境分別以密碼與救援金鑰還原，核對餘額、歷史與引用。損壞檔／錯誤解鎖／未知版本／還原中斷不破壞目前資料。效能以實測資料集記錄，未測不聲稱可支援任意資料量。

**交付**：第一個可日常試用的 Android 版本、已驗證功能清單、已知限制及可追溯版本。首批以可攜本機加密備份檔的匯出／還原為最低交付；雲端自動備份仍是後續必做 CORE，安排於 M2 前段，不能宣稱 M1 已具完整雲端備份。

M1 不包含完整信用卡、投資、預算／定期交易、OCR、銀行匯入或多裝置同步。這是 3A 的分批範圍，不是取消既有願景或降低資料保護標準。

## 階段 3｜M2：日常管理、雲端備份與信用卡

**前置**：M1 gate 通過，能以 M1 真實備份測試升級。M1 回饋中影響正確性／資料可靠性的問題優先修復。

1. **M2-01 持久背景工作與雲端備份**：將基礎 queue 完成到實際使用需要的 retry／backoff／idempotency；整合已驗證的雲端 adapter、版本與歷史、手動／自動備份及登入失效狀態。驗收離線記帳不受阻、失敗可重試、雲端下載後可乾淨還原；不上傳未加密的財務備份。不將備份誤稱 Sync。
2. **M2-02 預算**：期間與分類／帳戶／Tag 條件、已用／剩餘、門檻提示。沿用 1A 消費口徑；退款、轉帳與重疊預算不可雙算。
3. **M2-03 定期交易與提醒**：固定金額、日／週／月／年及每 N 期、候選項與確認入帳；驗證月末、閏年、離線補跑與 retry。通知失敗不能改變入帳狀態。首批採使用者確認；自動入帳若進一步納入，須另外完成其規則與安全驗收。
4. **M2-04 信用卡基本流程**：卡片設定、pending／posted、實際結帳／繳款日期、帳單歸屬、應繳與繳款分配、部分付款、基本額度資訊及提醒。從 M1 既有資料升級時不重複列消費；未支援 issuer 特例不假裝精確。
5. **M2-05 基本分期與跨期退款**：固定本金／明列費用、首期／週期、最後一期尾差；購買月份記總消費，應繳與繳款另算。驗證 pending 轉 posted、跨帳期退款及更正對剩餘計畫／帳單的影響。

**M2 gate**：預算、定期交易、信用卡與基本分期各自完成可用 UI、Domain、migration 及測試；所有新增權威資料可備份還原。M1 的收入支出、轉帳退款、搜尋報表與升級資料保持正確。雲端備份是真實可用路徑，不只是接口。

**交付**：可日常使用的第二批版本，新增預算、自動化基礎及完整首版信用卡能力。複雜 APR、進階融資、主附卡共額等仍依 rc1 延後。

## 階段 4｜M3：股票／ETF 與第一階段完整驗收

**前置**：Ledger／FX／費用、可靠 jobs、讀取模型與備份契約已穩定；有可驗證的行情／FX provider 路線。投資套件新增不改寫 M1／M2 的計算語意。

1. **M3-01 投資身份與買入**：股票／ETF、券商／投資帳戶、交易／費用／稅與原幣資訊、取得 lot；投資紀錄與帳戶扣款同一提交。
2. **M3-02 賣出與成本**：部分處分、Average Cost／FIFO、已實現損益；非法數量與版本衝突可辨識，重試不重複處分。
3. **M3-03 股息與基本 split**：現金股息和帳戶資金一致；拆股前後數量／單位成本變化正確，總成本不憑空改變。其他 corporate actions 沿 rc1 保留接口。
4. **M3-04 行情／FX 與估值**：整合已核實 provider、路由、快取、來源／時點、失敗與過期狀態；只有一個來源時不假稱多源容錯，缺資料不顯示假損益。
5. **M3-05 投資摘要與績效**：持倉、未實現／已實現損益、Total Return、Dividend、XIRR；區分無解／不收斂。投資專用流程不與一般消費混算。
6. **M3-06 rc1 全部 CORE 對照驗收**：逐項核對各 RC-01～RC-25 的 CORE 子集及原始追溯，涵蓋設計系統、搜尋、安全、雲端備份、匯入匯出、資料演進、平台、更新與發版治理。安裝／升級／回復、10～20 年／100k+ 交易目標資料集與關鍵效能都須有實際結果；未通過則保留未完成狀態。

**M3 gate**：每個已開放投資功能都能與 Ledger 核對；M1／M2 的真實舊版資料升級並完成所有模組的備份／還原；CORE 對照沒有未完成但被標記完成的項目。

**交付**：第一階段 CORE 完整版本。尚未開放的 Optional 能力仍保留 Full Vision、接口責任與後續接入路徑；不因本批完成刪除。

## 每個功能的固定工作方式

每次只推進一個可驗收的業務操作或合理子集：

1. 寫清楚操作與例子、所屬套件、影響資料與 RC／FV 來源。
2. 實作 Domain／Application／資料保存及必要 UI；有 schema 變更就一同完成 migration 與備份相容性。
