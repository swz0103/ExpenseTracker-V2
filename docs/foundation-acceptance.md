# Foundation Acceptance — 可執行測試的案例規格

狀態：案例已定義，尚未宣稱通過。所有金額都是測試資料。  
對應：[Foundation Contracts](foundation-contracts.md)、[RC-03／04](architecture-baseline-v1.0-rc1.md#rc-03)、[D-001](architecture-baseline-v1.0-rc1.md#a-plus-coordination)。

本文件是後續測試應驗證的外部結果，不以「函式有回傳」或 mock 回傳成功代替資料正確性。下列 USD／EUR 測試使用兩位 minor-unit scale，單純為固定 fixture，不宣稱全部幣別均為兩位。

## 基本金額與資料身份

- **VAL-01 精確計算**：0.10 USD + 0.20 USD = 0.30 USD；保存值為 30 minor units，JSON 金額為字串。不得經過 double 產生近似結果。
- **VAL-02 不相容幣別**：1 USD 與 1 EUR 直接加總應失敗；不得回傳 2。
- **VAL-03 尾差**：1.00 USD 分三期／三份，採既定最後項吸收規則得到 0.33、0.33、0.34；反向分配的總額仍精確等於 −1.00。
- **VAL-04 輸入與量化分開**：手動輸入不允許的三位 USD 金額會被拒絕；計算結果 0.005 USD 在 half-away-from-zero policy 下為 0.01，−0.005 為 −0.01。原政策版本與結果保存後，反轉直接取負。
- **VAL-05 範圍與序列化**：超出儲存整數範圍的金額拒絕；大整數匯出匯入字串後完全相同，不經 JSON number 失真。
- **VAL-06 帳本隔離**：命令在 workspace A 引用 workspace B 的帳戶／原交易時拒絕，兩邊餘額及 Audit 成功紀錄都不變。

## 日常記帳與財務語意

- **LED-01 期初與收支**：帳戶期初 100.00 USD，再收入 20.00、支出 5.00；餘額 115.00，期間一般收入只有 20.00、消費 5.00。
- **LED-02 同幣轉帳**：A=100.00、B=0；轉 25.00，結果 A=75.00、B=25.00，總資產不變、消費為 0。
- **LED-03 轉帳費用**：在 LED-02 加收 A 帳戶 1.00 費用，結果 A=74.00、B=25.00；消費只有費用 1.00，Fee component 不再額外扣款。
- **LED-04 跨幣實際金額**：A=200 USD、B=0 EUR；換出 100 USD，收到 92 EUR，另收 1 USD。結果 A=99 USD、B=92 EUR；消費是 1 USD 費用，保存兩邊原額與 0.92 EUR/USD 成交 context，不做 −101+92 的裸數字平衡。
- **LED-05 拆分類**：支出 10.00，兩個分類為 6.00 與 4.00；帳戶只扣 10.00，分類合計 10.00。若分類為 6.00 與 5.00 應拒絕整筆。
- **LED-06 跨月退款**：九月消費 60.00、十月退 20.00；九月消費保持 60.00，十月為對應退款減項 20.00，累計可退款餘額 40.00。若另提供原月淨消費分析，須明示不同口徑。
- **LED-07 超額退款競爭**：原消費 60.00，已有退款 20.00；兩個並行命令再各退 30.00，最多一個成功，不能以各自預覽看到 40.00 就累計退到 80.00。
- **LED-08 metadata 與財務更正**：改備註保留 revision 且餘額不動。將無後續依賴的支出 10.00 更正為 12.00，原支出／反轉／替代保留，淨消費 12.00、餘額淨扣 12.00；其中一步失敗不能只剩反轉。
- **LED-09 soft delete 與 reversal 不雙算**：允許刪除的普通支出 10.00 被 tombstone 排除時，餘額回復 10.00。另一個使用反轉的案例保留原 −10.00 加反轉 +10.00；UI 隱藏不能再排除原 −10.00 而憑空多出 10.00。

## 跨模組與崩潰恢復

- **TX-01 提交前故障**：在帳戶參與驗證、第一個業務寫入、Ledger 寫入、Audit／receipt 保存等節點注入失敗；所有權威資料與成功 receipt 都不留下半套結果。
- **TX-02 提交後回覆遺失**：交易已 commit，程序在顯示成功前終止；重開後用相同 operation ID／相同輸入重試，回傳原 IDs，餘額只變一次。
- **TX-03 ID 冒用**：相同 operation ID 改成不同金額重試，回傳 operation ID conflict，不改原結果。同金額的新意圖用新 ID 可正常保存。
- **TX-04 版本衝突**：預覽後帳戶被關閉或原交易出現不相容變更，提交時失敗；不能保存已過期預覽。
- **TX-05 後續工作失敗**：正式交易已提交但通知／報表失敗，回傳財務已成功且後續待完成；重啟後仍能從持久工作或版本重建恢復，不再次扣款。
- **TX-06 機制證據**：以真實 SQLite 寫入與中斷執行 TX-01／02；使用兩個獨立連線各自成功不能視為跨模組原子性通過。

## 預先檢查擴充邊界，功能仍按批次實作

- **EXT-01 分期與還款**：300.00 消費分十期，購買期消費 300.00、每期本金 30.00；第一期付款只清償 30.00，不新增 30.00 消費。期初信用卡經濟餘額為 0 時，購買後 −300.00、付款後 −270.00；付款銀行減 30.00。
- **EXT-02 股票買入**：10 股、每股 5.00 USD、費用 1.00；Investment 保存 10 股及可追溯成本資料，現金帳戶減 51.00；此操作不是一般生活消費。任一模組保存失敗，投資與資金都回滾。
- **EXT-03 部分賣出／split**：實作投資前補齊 FIFO／平均成本、費用分配、已實現損益、split 前後總成本 fixture；不能因 EXT-02 通過就宣稱投資已完成。

## 資料演進與保護

- **DATA-01 舊版升級**：固定舊 schema fixture 升級後，交易、原幣金額、revision 與餘額一致；故障時保留可恢復舊資料，不留下跨模組版本不一致。
- **DATA-02 投影重建**：刪除可重建 projection 後重算，結果與正式紀錄一致；不得因此丟失 Investment lot 等權威業務資料。
- **BACKUP-01 密碼還原**：全新環境、沒有來源裝置密鑰，僅以正確備份與密碼可還原；錯誤密碼不覆寫既有資料。
- **BACKUP-02 救援還原**：另一個全新環境、不提供密碼，僅以備份及文字救援金鑰可還原同一內容。
- **BACKUP-03 損毀與版本**：截斷、竄改、不認識的必要模組版本、空間不足及替換中斷，均不能把目前正式資料覆寫成半套或默默跳過資料。
- **BACKUP-04 去重連續性**：還原後對已提交 operation ID 重試，不新增第二筆財務效果；停用 UI 的模組資料仍包含在備份中。

DB／金鑰配對的 **KEY-01～08** 補充案例見[生命週期契約](storage-lifecycle-contract.md#8-必須執行的驗收)，涵蓋初始化、缺失／損壞、切換中止、回覆遺失、並行、容量故障、乾淨 Android 還原與清理保護。這些新增案例尚未執行。

## 執行紀錄要求

測試實作時記錄案例 ID、commit、工具鏈、資料集、執行方式及結果；區分 host-only、Android 裝置、migration 與 clean-restore。沒有 Android 執行環境時可先做 host 測試，但不能把它標為 Android gate 通過。

這份清單定義檢查目標，沒有任何案例因文件存在而自動變成通過；後續實際結果寫入獨立驗證紀錄。
