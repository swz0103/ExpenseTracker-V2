## 目前階段：階段 4 UI 重建

全專案健檢（189 項問題，P0 3 項）後決定：保留 `packages/` 的值物件與領域規則，重建儲存層、應用層與 UI。完整說明見 [ADR-0001](adr/0001-target-architecture.md)。

## 階段 0 已完成

- 寫入中被強制關閉後，SQLite 留下的 journal 不再被當成竄改；改由 SQLite 自行回滾（`storage_generation`）。
- 更正有標籤或商家的交易後，備份不再失敗（`modular_persistence` 標籤與商家驗證器）。

- 預覽版與正式版發佈前，必須先通過同一 commit 的完整驗證；只有發佈步驟持有寫入權限。
- 移除未使用的 `transaction_boundary` 原型、兩條手動 workflow、未使用的 Twelve Data 憑證畫面，以及過期文件。

### B. 功能缺口
- [x] 信用卡：卡片退款（只能退到消費金額，不含手續費）、作廢刷卡、作廢繳款，都在原日期沖銷並移出帳單（G6-04、G1-02 的卡片部分）。
- [x] 投資交易作廢：股利隨時可作廢；買進、賣出、分割只能從最新一筆往回作廢（後面的交易記錄了它改過的批次）；現金分錄在原日期沖銷，持股由剩下的交易重播（G6-04、G1-02 的投資部分）。
- [x] 卡片手續費調整與回饋：發卡行的年費、利息記為卡片費用，回饋與減免記為卡片入帳（G6-12）。
- [x] 帳單結轉前期未繳（或溢繳）金額（G2-12）；繳款日改為結帳後的第一個繳款日，結帳日早的卡同月繳（G2-08）。
- [x] 卡片手續費只能加、分期計畫自存結帳日（G2-12 其餘、G2-24）：費用可由發卡行入帳抵銷；分期計畫存自己的結帳日，結帳日變更不影響已排的分期。
- [x] 投資：同一持股只用一種成本法（G2-25）、同日 FIFO 依批次 ID 排序：ID 是 UUIDv7，等於買進順序且不受輸入順序影響，維持原設計（G2-19）、券商／投資帳戶／商品可改名且不影響已準備的交易（G7-14）。股利在全部賣出後仍可記：除息日在賣出前、股利晚發是常態，維持允許（G7-22）。
- [x] 投資交易依日期順序：買賣與分割不能早於最近一次賣出或分割，賣出與分割只算當天以前買進的批次（G2-05）。
- [x] 投資：淨額為 0 或負的賣出與股利（手續費大於成交價金時扣現金，淨額 0 不產生分錄，G1-06）；配股、減資、反向分割與現金減資（整股市場的畸零股以現金抵付，退還股款先沖減成本，G2-16）。
- [x] 跨幣摘要可帶入以當時匯率記下的成本、已實現與股利，只有市值用今日匯率（G2-01）；XIRR 改 ACT/365，現金流累計只變號一次就確定唯一解（G2-02、G2-21）。
- [x] 備份排程（G3-13）：`BackupService.runScheduled` 一次完成「到期就備份、有 Drive 就上傳」，不會丟例外；同帳號重疊執行會略過；失敗原因保留在 `BackupHealth.problem`，直到之後成功。App 在解鎖後與解鎖期間的定時器呼叫它（定時器接 UI 時做）。
- [ ] 背景喚醒與 4b-2 Android 平台、Keystore、固定簽章（G9-01、G3-21）：需要真機與使用者的簽章金鑰。
