# M1-06 簡易交易匯入的帳本邊界

目前只接收自有格式 v1 的一般收入與支出，包含日期、原幣精確金額、來源帳戶身分與備註；轉帳、退款、撤銷、更正、刪除、分類、Tag、商家及其歷史不在這個格式內。不可把這種交換檔當成完整帳本備份，也不可把只支援部分事件的匯出畫面稱為「全部匯出」。

匯入前先以唯讀預覽建立來源帳戶至目的帳戶的明確對應。正式提交在 Ledger 同一筆資料庫交易中重新讀取目的帳戶，核對版本、狀態、幣別與交易日期；每筆新交易經既有 `FinancialWorkflows`、receipt 與 Audit 寫入，非空備註在同一筆外層交易建立第一版。任一列失敗即回滾整批，包括先前已寫入的列；容量限制也在提交前與每列檢查。

來源去重鍵為「來源工作空間＋來源紀錄 ID」。來源資料的日期、種類、來源帳戶、幣別、小數位、最小貨幣單位與備註形成 SHA-256 指紋。鍵與指紋隨匯入事件的 `source_context` 存在權威 Ledger 中，受現有加密快照與乾淨還原保存，無須新增資料表或 schema。目標事件與 operation ID 由 V2 新產生，絕不直接重用來源 ID。重試同一來源且內容相同時回傳原事件 ID、不重複入帳；內容不同時回報來源列號並拒絕整批。已刪除或更正的事件仍保留來源事件列，因此重試不會重新入帳。若持久來源標記格式損壞或同鍵重複，匯入失敗封閉。

此批整合測試涵蓋 JSON 檔案解析後提交、同來源 CSV 重試、混合已匯入與新列、同來源內容衝突、第二列帳戶版本過期時第一列回滾，以及獨立加密帳本還原後重試。參見[主機證據](test-results/simple-import-ledger-host-2026-09-28.json)。目前尚無 Android 文件挑選／存檔介面、App 確認畫面、由完整帳本產生可宣稱無遺漏的交易匯出、5,000 列匯入容量／效能實測或實機與雲端 gate；M1-06 不標為完成。
