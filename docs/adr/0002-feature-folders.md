# ADR-0002：依功能分資料夾、帳本核心加模組、背景收件匣

- 狀態：採用（2026-10-27）。第 1 節由 PR-2 完成；第 2～5 節依 `claude/plan-2026-10-27.md` 分期施工，完成時在此標註。
- 取代：ADR-0001 中 App 內部分層（model／book／compose／pages）的部分。套件分層（core、domain、storage、vault、market）不變。

## 背景

功能清單（2026-10-26 審查）大約要加倍：對帳、預算提醒、專案、發票掃描、小工具數字、背景入帳等。照 model／book／compose／pages 分層，一個功能散在三、四個資料夾；`Ledger` 一個類別負責資料、規則、查詢、快取與寫入；有密碼的帳本只能在解鎖後寫入，背景什麼都不能做。

## 決策

### 1. 依功能分資料夾（PR-2，已完成）

```
lib/src/
  core/        帳本（ledger/）、外觀（look/、charts/）、共用元件（ui/）、導覽、偏好設定、效能紀錄
  features/    每個功能一個資料夾：model/（資料與服務）、ui/（頁面）、compose/（表單）
  app/         組裝：App、正式啟動、底部分頁、Android 通道、網頁預覽的範例帳本
```

規則由 `test/app/layers_test.dart` 檢查：

- `core/` 不引用任何功能，也不引用 `app/`。
- 功能可以引用 `core/` 與其他功能，但不能引用 `app/`；需要手機能力的功能（例如鎖定畫面的選檔與雲端硬碟）由 `app/` 傳入（`RestoreSources`）。
- `core/ledger/` 只引用自己與 `core/perf.dart`；只有 `table_journal.dart` 碰儲存。
- 各功能的 `model/` 與帳本都不碰畫面。
- 範例帳本只在 `app/demo/`，正式入口碰不到（`test/app/entry_test.dart`）。

測試也照同樣方式放：`test/core/`、`test/features/<功能>/`、`test/app/`。

### 2. 帳本核心與資料區（PR-4 完成）

原計畫把 `Ledger` 拆成核心加各功能模組、帳本不再依賴 Flutter。實作時改成較小、風險較低的做法：

- 帳本依資料區（`Area`：紀錄、帳戶、分類、預算、定期、行情）分別作廢快取。改預算不會重算信用卡帳單與餘額；行情更新只作廢市值相關的計算。`revisionOf(area)` 讓畫面判斷自己依賴的資料是否變了。
- `Ledger.watch(areas)` 只在那些資料區（加上隱藏金額等顯示變更）改變時通知；預算、定期、投資頁已改用它，記一筆不會讓沒關係的頁面重畫。
- 每月與每日的紀錄索引是延遲建立的，只在紀錄改變時重建。
- 不依賴帳本的純規則搬進 `packages/domain`（例如股票代號整理、可報價判斷、商品種類）；檢查、匯入、提醒仍需要帳本，留在 App。
- 帳本仍使用 `flutter/foundation`（通知）與 `Color`（分類顏色，深色模式要隨主題調整），但不碰畫面元件；`layers_test` 照舊檢查。完全脫離 Flutter 的效益不足以抵銷改動風險，暫不做。

### 3. 紀錄版本與升級（PR-3b 完成）

每列 JSON 帶版本號 `_v` 與寫入時間 `_at`，讀取時由 `upgradeRecord` 逐版升級，較新版本寫的資料拒絕讀取而不是誤讀；新增欄位一律選填、有預設值。刪除時在 `gone` 架記下 `架/id` 與時間（同一 id 再寫入就移除），為日後可能的同步預留。記一筆的暫存表單放在 `draft` 架，寫入不算帳本變更。

效能（PR-3b）：Argon2 金鑰推導與寫備份（含照片加密）在背景 isolate 執行；超過 2,000 列的帳本在背景 isolate 解析 JSON；SQLite 改 `synchronous=NORMAL`；行情快照解析後釋放原文。

### 4. 連接器（PR-3a 完成收盤價與匯率）

收盤價、匯率、雲端硬碟、手機資料夾等外部來源統一成 `Connector`：狀態、上次成功時間、錯誤、節流、重試。使用者動作的失敗一律顯示；背景失敗一律記錄，並在相關頁面標示。依附帳本金鑰的服務（備份、雲端硬碟、日曆、通知、行情）跟著開啟的帳本建立與結束，這是刻意的：鎖定後它們不該再碰帳本；跨帳本的狀態（例如「正在備份」）放在全 App 共用的靜態欄位。

Android 端（PR-3a）：`MainActivity.kt` 只留快速動作與隱藏畫面，其餘各一個 `ChannelPart`：`KeystorePart`、`PhotosPart`、`FilesPart`、`CalendarPart`、`RemindersPart`、`DrivePart`；Dart 端對應 `lib/src/app/android/`。頁面切換改用型別化的 `Place`（`core/nav.dart`），打開帳戶前確認它還在。

### 5. 背景收件匣與小工具快照（PR-7）

背景工作（WorkManager、通知按鈕）不打開帳本，只把待辦事項寫進收件匣。收件匣以帳本金鑰庫新增的 X25519 公鑰封裝：背景能寫、不能讀。解鎖時用私鑰讀出，經過與手動輸入相同的檢查後才入帳，需要確認的會列出來讓使用者過目。小工具只讀一份另存的彙總快照（本月支出、預算剩餘），不含任何明細，使用者可以關閉。

## 後果

- 一個功能的程式集中在一個資料夾，新增功能不必動到別處。
- 第 1 節只搬位置、不改行為；所有既有測試照舊通過即為驗證。
- 功能之間仍可互相引用；評估後維持現狀（頁面依賴帳本資料區而非彼此），等功能數量再增加時再考慮限制。
