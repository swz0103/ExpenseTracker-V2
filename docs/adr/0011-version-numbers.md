# ADR-0011：版本號的三碼各在什麼時候變

- 狀態：採用（2026-11-18）
- 補充：ADR-0010（每個版本留一份帳本與備份）

## 背景

0.17.0 之後 main 又合併了 21 次，每次都自動發布，版號卻都是 0.17.0：使用者手上的「0.17.0」可能是其中任何一次，標籤與測試帳本都說不清是哪一個。版號也沒有寫明哪一碼在什麼時候變，全靠當下判斷。

## 決策

版號寫成 `主.次.修`（`apps/expense_tracker/pubspec.yaml` 的 `version`）。`+` 後面的組建號由 CI 填入執行序號，不必改。

### 第一碼：主版號

使用者的資料或手機跟不上時才升。也就是**舊版 App 會讀不了新版寫出的資料**，或**有人會被留在後面**：

- 帳本或備份的格式改版，舊版 App 打不開新版的帳本或備份：`recordVersion`、`RowStore.schema` 或 `LedgerBackup.version` 升版。
- 加密方式改變，舊版 App 解不開。
- 最低支援的 Android 版本提高，有手機從此不能更新。
- 拿掉使用者在用的功能，或改變資料的意義（例如金額改用另一種單位存）。

1.0.0 之前第一碼固定是 0：全部實機驗收通過（[acceptance.md](../acceptance.md)）才升到 1.0.0。0.x 期間遇到上面的情況改升第二碼，並在 CHANGELOG 寫明舊版讀不了。

### 第二碼：次版號

使用者**看得到新的或不一樣的東西**，而舊資料照常可讀：

- 新功能、新畫面、新設定。
- 改版：畫面的樣子、排列、顏色、圖示、動畫明顯不同。
- 行為改變：算法、預設值、顯示的數字或文字的寫法變了（例如分期改寫成「首期…其後每期…」）。
- 新增要求的權限。
- 資料多了新欄位，但舊版 App 仍讀得懂（只是忽略它）。

### 第三碼：修訂號

使用者**看不到刻意的改變**，App 只是更接近它本來就該有的樣子：

- 修 bug：行為回到原本設計的樣子（例如溢出、出錯、數字算錯）。
- 效能、穩定性、無障礙的修補，畫面不變。
- 整理程式、補測試、更新套件，畫面與行為不變。
- 錯字、說明文字的小修正。

### 共同規則

- **每個會發布的 PR 都要升版**：動到 `apps/`、`infrastructure/`、`packages/` 的 PR，版號必須比 main 高，否則驗證的第一步失敗（`integration-validation.yml`）。只改文件、CI 或工具的 PR 不發布，不必升。
- **一次發布有好幾種改變時，照最高的那碼升**；升了某一碼，後面的碼歸零（0.17.3 → 0.18.0 → 1.0.0）。
- 版號只升不降、不重用。
- 每個版號在 CI 第一次發布時自動打上標籤 `v<版號>`，並有自己的 release，放 `ExpenseTracker-<版號>.apk`、`update.json` 與測試帳本；App 從 `releases/latest` 找更新（[android.md](../android.md)）。
- GitHub 上只留最新一版的 release 與標籤：新版公開後，舊的連同標籤刪掉（2026-11-21 起）。每版寫出的帳本與備份樣本留在 repo（ADR-0010），不靠標籤。
- 每個版號都要有 `whats_new.txt`（三行以內，給使用者看）、CHANGELOG 一節、[acceptance.md](../acceptance.md) 一節。

### 例子

| 改了什麼 | 升哪一碼 |
| --- | --- |
| 備份格式從 v3 改成 v4，舊 App 讀不了 v4 | 第一碼（1.0 前：第二碼，CHANGELOG 寫明） |
| 新增「月結報表」頁 | 第二碼 |
| 選顏色改成打勾樣式 | 第二碼 |
| 分期金額改用首期與其後每期的寫法 | 第二碼 |
| 320 dp 手機上預算卡溢出，修好 | 第三碼 |
| 記帳表單拆檔、補測試，畫面不變 | 第三碼 |
| 同時有新頁面與 bug 修正 | 第二碼（取最高） |

## 後果

- 使用者手上的版號就對得到一個組建、一個標籤、一份測試帳本。
- 忘了升版號的 PR 過不了驗證，而不是悄悄以舊版號發布。
- 判斷升哪一碼時看這份表；拿不準時取較高的那碼。
