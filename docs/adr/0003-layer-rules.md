# ADR-0003：分層規則由測試守住

- 狀態：採用（2026-11-14）；2026-11-21 改寫：`core/` 的部分與名稱改成現行的，拿掉已不用的工具與 600 行硬上限
- 取代：ADR-0002 第 1 節的引用規則

## 背景

0.9～0.14 依實機回饋快速改版後，審查發現：設計系統引用帳本、`core/` 根目錄混著平台服務與導覽；功能之間互相需要（帳戶與貸款、備份與鎖定形成循環）；三個頁面自己推路由；22 個檔案超過 600 行。規則只寫在文件裡時，每次快速改版都會被打破一點。

## 決策

1. **`core/` 分部分，每部分只能用表上允許的部分**（現行表與內容見 [architecture.md](../architecture.md#app-內部分層)）。設計系統不知道帳本；認得帳本的共用元件放 `core/widgets`。
2. **功能之間只能用對方的 `model/` 與 `forms/`，不能用 `ui/`，且不能互相需要（含間接）。** 兩個功能都需要的東西搬到 `core/` 或 `packages/domain`。
3. **頁面一律經 `Nav` 打開**，路由只在一處推（`openFullScreen`）。
4. **大小是提醒，不是上限**：檔案 600 行、函式 80 行時想想能不能依職責拆，不能拆就在上方寫明原因（[conventions.md](../conventions.md)）。
5. **以上每條都寫成測試**（`test/rules/layers_test.dart`，資料夾名稱集中在 `test/support/layout.dart`）；違反時 CI 失敗，例外寫在程式旁、看得見。

## 後果

- 新功能有固定的位置與邊界，改一個功能不會牽動別的功能的頁面。
- 搬檔用 `tool/move.py`，它會改好所有 import，整理的成本低。
