# ADR-0003：分層規則收緊，並由測試守住

- 狀態：採用（2026-11-14）
- 取代：ADR-0002 第 1 節的引用規則

## 背景

0.9～0.14 依實機回饋快速改版後，審查發現：

- `core/look`（設計系統）引用帳本；`core/` 根目錄混著平台服務與導覽。
- 功能之間互相需要：帳戶與貸款、備份與鎖定形成循環；設定頁直接放著備份、提醒、匯入的畫面。
- 三個頁面自己推路由，返回行為與網頁預覽要另外處理。
- 有 22 個檔案超過 600 行，最大的 1,767 行。

規則只寫在文件裡時，每次快速改版都會被打破一點。

## 決策

1. `core/` 分六部分：`text`、`look`、`charts`、`ledger`、`platform`、`ui`，每部分只能用表上允許的部分（[architecture.md](../architecture.md#core-的六個部分)）。設計系統不知道帳本；認得帳本的元件放 `core/ui`。
2. 功能之間只能用對方的 `model/` 與 `compose/`，不能用 `ui/`，且不能互相需要（含間接）。兩個功能都需要的東西搬到 `core/` 或 `packages/domain`。
3. 每個功能的設定頁放在自己的功能裡；「設定」與「更多」的入口頁在 `app/`。
4. 頁面一律是 `Place`；有自己「取消／完成」的整頁工作用 `openFlow`，它是唯一推路由的地方。
5. 檔案 600 行以內（產生的圖示檔與帳本狀態除外），用 `tool/split.py` 依主題拆。
6. 以上每條都寫進 `test/app/layers_test.dart`；違反時 CI 失敗，不靠人記。

## 後果

- 新功能有固定的位置與邊界，改一個功能不會牽動別的功能的頁面。
- 搬檔有 `tool/move.py`，拆檔有 `tool/split.py`，整理的成本低。
- 例外要改測試裡的清單，所以每個例外都看得見。
