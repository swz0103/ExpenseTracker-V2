# ExpenseTracker V2 功能完成矩陣

更新基線：`main`（2026-10-01）。完整候選由 `integration/v2` 快轉整合至預設分支；後續以單一 `main` 作為目前交付線。  
交付策略：先完成所有 M1／M2／M3 CORE 功能，再集中整合、效能、實機、CI 與發版。本次基線更新不代表正式發版。

本文件是功能狀態的唯一總表。個別功能文件保存規格與證據，但不得用較舊段落覆蓋本表的目前狀態。

## 狀態定義

- **已開放**：目前 App 預設 schema 可操作，且具 Domain、權威保存、升級、加密備份、UI 與直接受影響測試。
- **功能線完成**：功能本身具完整垂直切片，但尚未進入最後的全專案整合、實機與發版 gate。
- **Opt-in**：程式與定向測試存在，但 App 預設 schema 尚未開放。
- **部分完成**：只有部分垂直切片，或仍缺必要外部 provider／UI／保存契約。
- **待做**：尚未形成可操作功能。

所有狀態都不自動代表主機全量、GitHub Actions、Android 實機、100k 容量或正式發版已通過；這些在功能完成後集中驗收。

## 多來源市場資料契約

市場資料不得綁定單一供應商。每個 provider 以獨立 adapter 註冊至 provider registry，並宣告支援的市場、商品、幣對、歷史深度、更新型態與授權需求。

每個查詢路由支援：

1. **自動優先序**：依 registry 註冊順序，並可用 `preferredProviderIds` 把指定 provider 提前。尚未依資料新鮮度或額度重排，來源偏好也不會跨次啟動保存。固定來源見下一項。
2. **指定來源**：使用者固定選擇 provider，不自動換源。
3. **明確 fallback**：主要來源失敗後使用備援，結果必須顯示實際來源與原因。
4. **多源核對**：並列不同來源及差異，不靜默平均或選擇對 App 最有利的數值。

每筆市場結果至少保存或呈現 provider ID、dataset、商品／幣對、觀測時間、取得時間、原始或調整狀態、反向／換算等衍生方式、是否過期，以及 attribution。不同來源的 observation time 或 adjustment policy 不一致時，必須回報衝突。

行情與參考 FX 只用於估值與提示；已入帳的成交與換匯仍以使用者確認的實際金額為權威。

## 每條功能線的完成證據

功能工作線完成前必須同時具備：

1. 明確業務規則、輸入限制與錯誤語意。
2. 權威資料、操作 ID、稽核與原子提交。
3. 必要 schema 升級、中斷回滾與重試。
4. 加密可攜快照及密碼／救援文字乾淨還原。
5. 可操作 UI、隱私遮蔽、取消與結果不明後重試。
6. 該功能的正常、邊界、失敗、重啟與直接受影響回歸。
7. 明列尚未執行的外部帳號、實機或最後整合 gate。

只有上述七項齊全才可從「部分完成」或「Opt-in」提升為「功能線完成」。
