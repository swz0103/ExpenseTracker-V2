# 拆分的平均、百分比與固定比例分配

2026-09-28：由 [PR #56](https://github.com/swz0103/ExpenseTracker-V2/pull/56)（`d6c1a24fed4e6cfd5116bd1253e8a183214916f1`）接續。[手動多分類拆分](split-entry-drafts.md)已具備金額保存、凍結送出與明細；本批補上 [Full Vision FV-016](full-vision-baseline.md#fv-016) 已列出的三種分配方式，對應 [RC-03](architecture-baseline-v1.0-rc1.md#rc-03)、[RC-04](architecture-baseline-v1.0-rc1.md#rc-04) 與 [M1-04](implementation-plan.md)。

## 使用流程

拆分表單的「分配拆分金額」讀取目前交易總額、幣別與 2～16 項分類順序。使用者選平均、百分比或固定比例，先「預覽分配」，確認每項結果後才「套用分配」。修改任何比例或分配方式會取消舊預覽，重新計算後才能確認。取消不改原有金額。

- 平均：每項權重相同。
- 百分比：每項必須大於零，十進位合計精確等於 100%；99.99% 不會自動補成 100%。
- 固定比例：每項填正十進位數，例如 1：2：3 或 0.1：0.2：0.3，兩者分配相同。每項最多 128 字元、18 位小數，不接受科學記號、算式或百分號；超長貼上整筆拒絕，不截斷數值。
- 總額必須先是有效正金額；未套用的計算式不能直接當總額。任何項目若不足一個最小貨幣單位而成為零，整份建議拒絕，請調整比例、總額或項目數。

分配使用既有 `Money.allocate` 和 `truncate-last-remainder-v1`：前 N−1 項捨去不足最小單位的部分，最後一項取得剩餘總額。總和必須與交易總額完全一致。例如 TWD 10.00 平均三分為 3.33／3.33／3.34；1：2：3 為 1.66／3.33／5.01。預覽明列最後一項的尾差，不另建浮點運算或第二套帳本算法。

## 保存與安全邊界

比例設定及預覽是暫時的輸入輔助，尚未確認時不寫入草稿、不產生交易。確認後只把每項實際金額一次寫入原有加密拆分草稿；保留草稿 ID、分類、日期與其他欄位。重啟仍按已確認金額繼續，正式入帳走相同分類、合計、凍結命令與原子提交檢查。

背景鎖定會關閉分配視窗、隱藏分類及金額，並保留先前已保存的草稿。即使確認回呼已排隊，舊畫面 epoch 也不能跨鎖定套用。未確認的比例編輯不保存；鎖定後重新開啟從平均模式開始，不冒稱完整保存暫時視窗。

沿用 schema 9、snapshot 8 及 `manual-split-entry-v1`；資料庫、帳本、還原器及金鑰管理程式未改。沒有新增 migration，也沒有讀取舊 App 的資料。分配模組放在現有 `amount_input` 業務套件，UI 不直接操作 Ledger 私有資料。
