# 本輪可安裝試用版交付計畫

依 2026-09-27 使用者最新指示：排除需要實機的操作，持續到使用者回來，或完成可安裝到手機的程度，且經過大規模測試。本輪停止點是有實際輸入流程的 M1-01 最小試用 APK，不是既有固定假資料的地基按鈕。

這是本輪優先順序調整；[完整 M1～M3 計畫](implementation-plan.md)和全部 CORE 不刪除。試用版不等於 M1-07 全部驗收或正式發版；未通過的實機、安全與 migration gate 仍明列。

## 可交付路徑

1. 建立獨立試用 App 身份及私人資料目錄，不覆蓋地基原型。最小設定包含解鎖密碼、救援文字保存確認、初次空帳本。
2. 新增現金／銀行帳戶、期初餘額、收入／支出、日期、帳戶摘要及分頁交易列表。精確金額、workspace、Audit、穩定 operation ID、重試與失敗回滾沿用既有契約。
3. App 離開前景後鎖定；恢復需解鎖，操作層同時受鎖定狀態保護。平台金鑰使用安全儲存，畫面保持簡潔。
4. 可匯出實際加密備份並用密碼或救援文字匯入；讀回驗證、完整內容與 receipts 保存、受控世代替換、錯誤保留原資料。備份憑證與解鎖設定的延續要有明確行為，不默默換 key。
5. 產出可側載 debug APK、hash、測試結果及已知限制；不購買、不公開 repo、不簽署正式發版，也不自動安裝或操作手機。達成本輪交付後停止自動推進，等使用者驗收。

分類／Tag／Merchant、退款更正、完整轉帳 FX、報表／CSV、信用卡及投資保持後續里程碑，不用未完成按鈕假裝可用。試用版不先增加所有未來模組。

## 實作順序

- **P1 操作工作階段與讀取**：取得生命週期排他權後建立有界 session；不在每次 UI 操作重新匯出整份 snapshot。公開 session 以外不流出 DB handle，關閉／備份／還原與晚到命令有明確順序；沿用未知 schema 拒絕。
- **P2 設定與最小畫面**：設定／鎖定、帳戶／收支／列表與操作去重，備份匯入匯出一同接入；獨立 widget／host 整合驗證。
- **P3 大規模與故障**：使用真實 SQLite／SQLCipher 及獨立期望值執行長期資料、批次／重複操作、並行、溢位、錯誤密碼、損毀／未知格式與還原中止；找出失敗後修正，不只報測試數量。
- **P4 建置及交付**：完成全套 CI、APK 封裝核對、安裝說明與限制，保留每項分支／依賴 PR；不自行合併 main。

## 大規模測試與容量契約

目標包含二十年日期範圍與至少 100,000 次有可核對預期結果的財務操作／重試；記錄帳本數、實際成功交易數、重試數、筆數分布、執行時間與測試硬體，不能把重試或屬性組合冒充同一帳本的成功交易數。

另外建立逐步增大的單帳本資料，實測正常讀寫、分頁、備份／還原時間與大小。既有原型是 16 MiB payload／50,000 權威資料列上限，不能直接宣稱支援 100k 筆單帳本。試用版必須在接受超過已驗證容量的新帳務前拒絕，或先完成擴容並通過實測；不能讓帳本持續增加到再也無法備份。

容量上限是使用者可理解的試用限制，最終值依實測訂定並記錄；未驗證任意資料量，不硬寫成功。M3 的 100k+ 長期效能目標仍保留，不因本輪試用版分批實作而刪除。

## 排除項目與結果分級

本輪不進行 adb／手機重啟／實機操作，未新增真實裝置證據。先前 SM-A5660 的地基測試仍可引用，但不能冒充新 App 或新設定流程已實測。編譯成功、host 整合、widget 測試、故障／效能與 Android 裝置結果分別記錄。

未知舊版資料仍應拒絕開寫；完整產品升級協調器未完成時，試用 APK 不提供未驗證的就地升級捷徑。保留已知 snapshot 的加密匯入路徑，未完成 gate 不標 verified。
