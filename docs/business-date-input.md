# 共用日期輸入與繁體中文月曆

2026-09-27，依賴 [PR #52](https://github.com/swz0103/ExpenseTracker-V2/pull/52) 的背景鎖定保護。對應 [M1-02](implementation-plan.md#m1-02分類tagmerchant-與日常錄入)、[RC-02](architecture-baseline-v1.0-rc1.md)、[Full Vision Q048](full-vision-baseline.md#q048) 與 [Q155](full-vision-baseline.md#q155)。本批是既有日常錄入的共用元件，不宣稱全部 M1 或設計系統完成。

## 可用行為

帳戶起始日期與收入／支出日期使用同一欄位。可手動輸入 YYYY-MM-DD，也可開啟繁體中文月曆；選中一天後必須按「確定」才寫回欄位，取消保留原文。欄位保留鍵盤輸入，不另開使用地區格式的第二個日期文字解析器。

未填完、不合法或空白文字不在開啟月曆時被自動修正。月曆先顯示今天，僅在確認後替換原文字。草稿仍保存原文；正式入帳走原有 BusinessDate 嚴格驗證，例如 2023-02-29 不會變成 3 月 1 日。手動欄位遵守草稿 32 個 UTF-16 單位上限，過長貼上整段拒絕，不截斷成另一個日期。相同日期確認不多寫一次草稿。

BusinessDate 支援 0001-01-01 至 9999-12-31，月曆保留相同範圍，沒有另加未決議的過去／未來日期限制。此為民用年月日；月曆內部用 UTC DateTime 承載日曆欄位，所有加日／加月及星期運算均以該欄位為準，沒有呼叫 toUtc／toLocal 轉換。今天取裝置本地年月日；不把今天定義成 UTC 當日。這避免在歷史時區變更跳過午夜或整日的情況下，日曆偷偷改寫日期。

本批未新增發生時間、入帳時間或原始時區資料；[Q026](full-vision-baseline.md#q026) 的完整時間模型仍待後續實作，不能用月曆替代。

## 草稿與鎖定邊界

月曆只提出欄位值，不直接入帳。確認後與手動輸入共用既有加密草稿保存回呼；凍結送出的表單不能修改日期。

開啟時捕捉 controller、編輯版次及擁有者的 session/page 條件。等待結果期間若原文字被修改（即使改回原文）、欄位被停用／更換，或 session／頁面已失效，舊結果不得覆寫目前欄位。App 鎖定沿用 #52 的 PopupRoute 清除；即使已按確認但 continuation 尚未執行，也必須重新核對 view epoch。未通過就保留既有已接受的草稿，等待重新解鎖。

## 失敗後保持可見

完整回歸發現：帳戶表單增加日期欄位高度後，使用者在底部送出不合法內容，頂端錯誤訊息可能尚未建置而留在畫面外。現在同一頁、同一解鎖工作階段發生操作錯誤時，下一畫格回到頁首，保留原欄位並顯示原有 live region 提示。切頁／鎖定後失效的操作不得把舊錯誤帶入新工作階段。捲動控制器隨頁面使用且不保存不同頁面的舊位移。

既有「不合法表單／重複點擊」測試增強為錯誤實際位於可見範圍、失敗時帳戶與事件皆為空、按鈕確實命中兩次。新日期整合測試先等待畫面上的加密草稿保存完成，再從 engine 讀取；保留 engine 的忙碌保護，不把測試同步問題改成放寬併發。

## 語系與版面

App 明確使用 zh_TW，載入 Flutter 官方 Material／Widgets／Cupertino 語系 delegate。新增 SDK flutter_localizations 與已快取的 intl 0.20.3；其他依賴版本未升級。

共用日期元件、金額計算器及 App 名稱改由 ARB 管理，使用 Flutter gen-l10n 產生型別化存取。app_zh.arb 是目前繁體中文基底；app_zh_TW.arb 宣告台灣語系並繼承，避免同一批文字重複維護。產生後的 Dart 一同保存，修改 ARB 後重跑 flutter gen-l10n；一般 flutter pub get／build 亦會產生。

金額計算結果仍用 Money 的精確十進位字串，不為文字格式轉成 double。既有其他頁面的文字與所有日期／數字顯示尚未全部移入語系層；目前只有繁體中文，沒有宣稱多語系已交付。

320 × 740、文字縮放 3.2 的案例重現 SDK 月曆標題固定高度溢出 20 px。縮短按鈕文字不足以修復；最後調整月曆標題樣式為 titleLarge，保留完整日期與系統文字縮放，未移除溢出檢查或把文字縮小為不隨系統放大。原生月曆仍遵守 Flutter 本身的縮放上限；實際 Android 字型、橫向、TalkBack 與螢幕閱讀器體驗另待裝置驗收。

## 驗證與相容性

[本機驗證證據](test-results/business-date-host-2026-09-27.json)保存最終執行範圍、失敗修正、來源指紋與 APK 資訊。有效案例包括：

- 真正點選閏日、確認／取消、相同日期不重寫、部分／錯誤日期不被正規化及過長貼上拒絕。
- 範圍兩端、歷史跳日日期與不經時區轉換的日曆運算；窄螢幕大字體、月曆標示及日期欄位觸控大小檢查。
- 文字已變更與立即鎖定但尚未 rebuild 的排隊結果拒絕；實際 App 背景生命週期清除月曆、保留原草稿與餘額。
- 實際帳戶與支出表單選取閏日；非法日期入帳失敗後，草稿鎖定／還原／修改再送出。
- 真實 SQLCipher：不合法草稿重啟保留、提交後回覆失敗不重複入帳、0001／9999 年及閏日完整保留；移除合成來源 DB 與 vault keys 後，密碼與救援憑證分別在乾淨環境還原，重開並核對完整 snapshot bytes、日期與餘額。
- 整個 App 因語系設定變更而回歸，涵蓋既有分類／商家／Tag、草稿、隱私、升級及安全還原。

沒有 schema 7／snapshot 6／manual-entry-v1 變更，沒有新金融或加密規則。五千筆資料、底層完整主機清單與程序中止證據沿用相同核心的 [PR #51](amount-calculator.md)／[草稿驗證](manual-entry-drafts.md)，本批不重跑未受影響核心或冒稱重新通過。沒有操作手機、啟用 Actions、修改 branch protection 或合併 main。
