# M1-06 簡易交易匯入的帳本邊界

簡易匯出只收錄普通收入／支出：來源事件 ID、日期、原帳戶 ID、幣別與精確金額、最新備註。它逐頁讀取有效事件，期初與轉帳、退款、撤銷、已被更正／撤銷的原交易不寫入，並在畫面顯示期初及其他略過數；已刪除紀錄不參與有效事件讀取。帳戶設定、期初餘額、分類、標籤、商家及備註修訂歷史一律不在此格式內，即使普通收支有這些附加資料也會省略，故 UI 必須明確提醒：這是**未加密的局部交換檔**，不是完整帳本匯出或可還原備份。需要完整保留時使用獨立的加密備份。選儲存位置時 App 鎖定，解鎖後才準備明文與執行第二次確認；Android 寫入後回讀核對，不完整時回報錯誤。

大量資料主機 gate：同一來源 4,999 筆可一次寫入並完整重送去重；目的帳本另有 1 筆期初事件，因此 5,000 列交換檔中的第 5,000 筆新事件會因帳本容量上限而整批拒絕，沒有部分成功。Windows 主機的約 23 秒寫入與約 4.7 秒重送量測見證據，不代表 Android 實機效能。來源工作空間與目的帳本相同時在唯讀預覽階段拒絕，避免將自己的匯出再次匯入造成重複入帳。

App 協調層現已可接收 JSON／CSV 文字，依使用者指定的來源／目的帳戶對應讀取目前帳戶，先產生唯讀審閱物件；**只有明確呼叫確認**才整批寫入。審閱物件綁定建立時的解鎖 session，鎖定、重新解鎖或還原後不能沿用舊審閱；確認時仍由 Ledger 在同一資料庫交易內重新查帳戶。確認期間若鎖定 App，先等待已接受的匯入完成或回滾，再關閉資料庫；回應可因鎖定而失效，來源去重使重新審閱／重試不重複入帳。密碼與救援憑證的乾淨還原後去重已加入 App 整合測試。

Android 介面現透過系統選檔器先保存檔案 URI；選檔若令 App 離開前景，使用者須重新解鎖後才讀取檔案內容。讀取以 24 MiB 上限與嚴格 UTF-8 解碼；App 不將選取的明文寫入私有檔案。畫面逐一指定目的帳戶、核對筆數及逐幣別收支，金額被遮蔽時不能確認；最後仍要在確認對話框明確同意才寫入。此流程已有主機 widget 測試與 Android ARM64 debug 建置，但**尚未實機操作選檔器**。可宣稱無遺漏的匯出與 5,000 列匯入效能也未完成。

目前畫面最多接受 64 個不同來源帳戶 ID；超過時在建立帳戶對應 UI 前拒絕，以免在手機上一次產生數千個選單。格式與 Ledger 的單批 5,000 筆上限不因此改變；64 個以上來源帳戶的 UI 流程屬延後項目。

目前只接收自有格式 v1 的一般收入與支出，包含日期、原幣精確金額、來源帳戶身分與備註；轉帳、退款、撤銷、更正、刪除、分類、Tag、商家及其歷史不在這個格式內。不可把這種交換檔當成完整帳本備份，也不可把只支援部分事件的匯出畫面稱為「全部匯出」。

匯入前先以唯讀預覽建立來源帳戶至目的帳戶的明確對應。正式提交在 Ledger 同一筆資料庫交易中重新讀取目的帳戶，核對版本、狀態、幣別與交易日期；每筆新交易經既有 `FinancialWorkflows`、receipt 與 Audit 寫入，非空備註在同一筆外層交易建立第一版。任一列失敗即回滾整批，包括先前已寫入的列；容量限制也在提交前與每列檢查。

來源去重鍵為「來源工作空間＋來源紀錄 ID」。來源資料的日期、種類、來源帳戶、幣別、小數位、最小貨幣單位與備註形成 SHA-256 指紋。鍵與指紋隨匯入事件的 `source_context` 存在權威 Ledger 中，受現有加密快照與乾淨還原保存，無須新增資料表或 schema。目標事件與 operation ID 由 V2 新產生，絕不直接重用來源 ID。重試同一來源且內容相同時回傳原事件 ID、不重複入帳；內容不同時回報來源列號並拒絕整批。已刪除或更正的事件仍保留來源事件列，因此重試不會重新入帳。若持久來源標記格式損壞或同鍵重複，匯入失敗封閉。

此批整合測試涵蓋 JSON 檔案解析後提交、同來源 CSV 重試、混合已匯入與新列、同來源內容衝突、第二列帳戶版本過期時第一列回滾，以及獨立加密帳本還原後重試。參見主機證據。目前尚無 Android 文件挑選／存檔介面、App 確認畫面、由完整帳本產生可宣稱無遺漏的交易匯出、5,000 列匯入容量／效能實測或實機與雲端 gate；M1-06 不標為完成。
