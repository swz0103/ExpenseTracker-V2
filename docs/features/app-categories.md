# App 分類與 V2 帳本升級

後續版本新增[交易標籤與 schema 6](transaction-tags.md)；本文保留分類接入時 schema 5 的範圍與驗證證據，現在的 App 目標格式及最新開發包以[工作進度](../work-progress.md)為準。

本批接續 [分類引用與世代升級](../foundation/ledger-reference-upgrade.md)，屬於 [M1-02](../delivery/implementation-plan.md#m1-02分類tagmerchant-與日常錄入) 的分類子集。Tag、Merchant、交易拆分編輯及其他 M1／M2／M3 CORE 仍待實作；本批不代表 M1 完成。

來源：[RC-05](../architecture/architecture-baseline-v1.0-rc1.md#rc-05)／[FV-011](../architecture/full-vision-baseline.md#fv-011)。本批只把已驗證的分類業務透過 App 接入；不改寫 Full Vision 或把尚未交付的標籤／商家標成完成。

## 可以操作的流程

- 新帳本使用支援分類引用的 V2 schema 5。首頁可進入管理分類，建立收入／支出分類與同類型的第二層分類，改名、封存或重新啟用。
- 一筆收入／支出可選擇同類型的有效分類，或保留未分類。分類金額只是分析歸屬，不會額外增加一次現金流；期初餘額不當作收入。
- 交易保存分類 ID、預期版本與入帳時歷史序號。重試沿用操作 ID；改名或封存不改寫交易的原始分類引用。最近交易顯示該 ID 目前的名稱及封存狀態，不將目前名稱冒充當時名稱。
- 有有效子分類的父分類不能直接封存。分類表單與記帳使用既有公開業務接口，不直接改分類私有表。
- 輸入錯誤保留表單；背景鎖定清除畫面與憑證，已接受操作依原有提交規則完成或回滾，重新解鎖後確認結果。

### 後續分類管理操作

`feat/category-management` 基於已驗證的 App 升級分支接上搬移與合併，沿用現有 schema 5、公開 CategorySession、歷史記錄與備份格式；沒有新增資料表或金融語意。

- 活躍分類可改上層或提升至第一層；只提供相同收支類型的活躍第一層候選，業務規則仍拒絕第三層、非法父子及版本衝突。
- 有子分類／歷史子分類的父分類不能直接合併；尤其已合併的歷史子分類仍保留原父關係，本批沒有自動搬移這些歷史關係的流程，不用 UI 繞過既有保護。
- 合併必須選擇同類型活躍目標並點選「確認合併並保留歷史」。畫面說明來源不再供新交易選用，以及沒有直接還原合併的按鈕，不自動依名稱合併。
- 原分類、原交易 ID／版本與歷史序號保留；歷史畫面顯示來源名稱及目前合併去向。重送不重複搬移／合併，來源與目標的預期版本都須核對；跨 workspace 不允許操作。
- 取消編輯會清除該操作的目標／父分類，避免從收入分類返回新增支出分類時保留不相容的選項。合併後來源不再顯示編輯入口；原始引用仍可備份與還原。

此追加批次的實際驗證結果與開發安裝包以[最新進度](../work-progress.md)為準；下方大量資料結果屬於前一批完整整合，後續 UI 改動不冒稱已包含在舊 APK 或舊大量 run 中。

## 備份與容量

新格式匯出包含分類、歷史與交易分攤。匯入已知較舊的 V2 備份時，先正規化到目標格式並做 App 範圍／容量准入，再經既有加密暫存完整驗證與原子替換；不能直接在原 DB 上改格式。匯入前仍保存原帳本雙憑證安全副本，匯入後的新備份使用本 App 原有憑證。

單一 workspace 檢查同時涵蓋帳戶與分類，所以只有分類、尚無帳戶的備份也不會錯認為空帳本。混合 workspace、未知格式、超額或非法金融資料拒絕後，現有帳本保留。

目前仍是受限的 App 工作階段：32 帳戶、5,000 事件、256 分類、1,024 次分類變更，以及跨表 50,000 列／16 MiB 等保護；不是 M3 的單帳本 100k+ 容量承諾。

## 驗證與限制

本批驗證涵蓋既有 App 回歸、schema 3／4 升級、原始 DB／key／profile 保留、兩種憑證、故障後新引擎接續、背景鎖定、分類歷史與重試、小螢幕操作及舊格式備份匯入。實際完成範圍與結果記錄於 [工作進度](../work-progress.md)。

[App 大量資料原始結果](../test-results/2026-09-27/app-category-scale-2026-09-27.json)已通過：從只有一筆期初的 schema 3 帳本完成升級，再建立至 5,000 事件／4,999 分攤／256 分類／768 次分類變更；5,002 次重送、全分頁、滿額拒絕、完整 snapshot 7,564,696 bytes 與獨立計算餘額 509,600 minor units 均符合。刪除測試來源 DB 與 vault keys 後，分別用密碼／救援文字在獨立目錄還原，再核對全資料、歷史版本、重送及重新解鎖。

此 App 案例的升級前只有期初一筆；不是 5,000 筆既有 App 帳本的升級。底層已有資料的大量升級另由 Ledger 整合測試覆蓋，不能混算成同一資料集。App 案例約 374.28 秒，與其他回歸並行執行，不是 Android 實機或隔離效能保證。可在 `prototypes/expense_preview` 以 `dart run tool/category_scale.dart` 重現，僅使用合成資料與測試 vault。

尚未執行此批 Android 真機 secure storage、系統檔案選擇器、OS／斷電驗收。GitHub Actions 依額度政策停用；本機通過不能替代雲端或實機 gate，沒有正式發版或合併 main。
