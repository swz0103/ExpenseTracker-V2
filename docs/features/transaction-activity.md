## 使用流程

交易選單新增「查看活動」；轉帳在雙帳戶摘要下提供同一入口。列表以記錄時間由新到舊呈現。選取支出或其中任一退款，都可查看該原支出及全部相關退款；其他交易顯示自己的入帳記錄。每次讀取 30 筆，以「載入較早活動」繼續，不受首頁最近交易的 30 筆限制。

- 交易日期是原有民用日期；記錄時間來自既有 audit 的 UTC instant，畫面轉為本機時區，兩者分別標示。
- 目前選取交易有文字標記；技術 ID、operation ID、SQL、內部版本均不顯示。
- 轉帳保留雙幣本金與手續費區分，跨幣退款另顯示原幣沖回額，沿用現有 Money 元件。
- 金額及無障礙語意沿用開啟時的隱私設定。App 背景鎖定會立即隱藏並移除活動浮層，未完成的讀取不能跨解鎖階段返回資料。
- 讀取失敗顯示可重試訊息；已載入活動及帳本保持原狀。查閱不會建立 receipt、財務事件或新 audit。

## 業務邊界與排序

`LedgerSession.activity` 擁有資料查詢，App 只使用不可變的 `LedgerActivity` 與不透明游標。原支出、退款關聯、事件與 audit 均以 workspace 關聯；未知或其他工作區的交易拒絕查閱。游標同時綁定工作區與原交易，不可拿另一個交易的游標跳頁。

查詢重用既有事件讀取映射及退款索引。每頁限制 1～100 筆；先按完整 UTC 記錄時間降序，再按事件 ID 固定排序同時刻資料。UTC instant 可有 0～6 位小數，SQL 先補齊到 6 位後比較，避免 `...03Z`、`...03.1Z`、`...03.100001Z` 直接字串比較顛倒時間，也不經 SQLite 毫秒日期函式或浮點轉換損失精度。此時間是既有本機紀錄，不代表外部認證時間或跨裝置全序。

沿用 schema 10／snapshot 9；新查詢亦支援較早 V2 格式，沒有新表、新快取或獨立權威帳本。備份原本即保存事件、退款關聯與 audit，乾淨還原後以相同資料重建列表。重送已完成操作不產生第二個活動。

本批[受影響範圍 54 個獨立主機案例](../test-results/2026-09-28/transaction-activity-host-2026-09-28.json)通過，新增 5 個；包含 65 事件分頁／時間精度、32 事件窄畫面／雙倍字體、刪除來源 DB 與金鑰後的雙路乾淨還原及既有選單／隱私回歸。初期畫面測試等待繪製的修正另列證據，不重複計數。基礎退款沿用 #58 的完整 18 套件／810 案例、5,000 事件及程序中斷證據；本批只重跑受影響範圍，不宣稱重新完成整輪主機或大量資料檢查。

目前活動列表包含既有收入、支出、轉帳、期初及退款入帳。分類／標籤／商家改名歷史、歷史名稱檢視、一般編輯 revision、正式 reversal、tombstone 與相關恢復仍待完成；帳戶名稱沿用目前名稱。此查閱流程是 M1-04 的一部分，不等於完整 Activity Timeline 或 M1 gate 完成。更正或刪除原支出時仍須先處理退款依賴，禁止令既有退款超額、孤立或改變歸屬。
