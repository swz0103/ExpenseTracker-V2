# 多分類拆分、加密草稿與明細

2026-09-28：依賴 [PR #55](https://github.com/swz0103/ExpenseTracker-V2/pull/55)，實作 M1-04 的拆分收支使用流程。Ledger 與 Money 原則追溯 [Architecture Baseline rc1](../architecture/architecture-baseline-v1.0-rc1.md#rc-03) 與 [Full Vision FV-016](../architecture/full-vision-baseline.md#fv-016)／[Q006](../architecture/full-vision-baseline.md#q006)。退款、更正、撤銷、刪除與活動歷史仍另批完成，不把拆分完成等同 M1-04 全部完成。

## 已接入的行為

日常收支可選擇「拆分多個分類」，填入 2～16 項分類與金額。每項均須為同一收支類型的可用分類、分類不可重複、金額大於零且符合帳戶幣別精度；合計必須精確等於交易總額。手動輸入不四捨五入，算式沿用既有計算器，確認套用後才是可入帳金額。總額與差額使用整數最小單位運算。

Allocation 僅分配分類歸屬，一筆拆分收支仍只有一個金融 leg、一個事件、一份操作收據，不把每個分類重複計入帳戶餘額或收支。分類 ID、送出時版本及序列沿用既有不可變歷史保存；列表使用該 ID 的目前名稱／封存／合併標示，不追隨合併改寫交易，並顯示每項實際歸屬金額。這不是宣稱列表可顯示交易當年的分類名稱。

列表明細沿用 MoneyView，隱藏金額時畫面與讀屏均無各項數字。窄畫面直向排列；背景鎖定清除表單和分類彈出選單。複製拆分交易保留分類結構，可用分類沿用，停用分類保留待選空位；總額、每項金額與日期留白，新交易使用新的操作 ID。超過本表單上限的舊拆分明確拒絕複製，不截斷分類。

## 草稿與失敗恢復

新增 `manual-split-entry-v1`，保存每行原始金額文字及可空分類；部分輸入、未計算算式與不合法合計仍能保存草稿，沒有金融效果。最多 16 行，每行沿用 128 字元限制及既有 16 KiB 加密內容上限。舊 `manual-entry-v1`、`manual-transfer-v1`、`manual-fx-transfer-v1` 格式不變。舊版不認識新格式時拒絕讀取並保留原檔，不把各項誤當整筆總額。

送出前凍結每項精確金額、分類版本、帳戶版本、日期與同一事件／操作 ID。分類在提交前變更時回報衝突；使用者明確返回編輯後才可重選或採用新版本。已提交但沒收到回覆時用原收據比對，重開與重試不重複入帳，即使分類之後改名或封存仍可核對原操作。尚有草稿時，匯出、還原與升級沿用既有待處理 gate。

## 相容與回查修正

沿用 schema 9／snapshot 8：schema 5 起 Allocation 已可保存多項分類，本次沒有新增資料表、欄位或改寫事件含義，因此不為表單另外升級實體 schema。schema 8 → 9 既有路線仍必須先處理草稿、建立並驗證雙憑證安全備份再發布。大量驗證包含舊 V2 schema 8 的拆分入帳後升級，並保留相同歸屬。

16 項測試找出原來 `posting-v2` 收據沿用 1,024 bytes 上限，造成合法多分類交易被拒絕；有 Tag／Merchant 的同類交易卻已有 4,096 bytes。現在有分類收據一律使用既有 4,096 bytes 上限，寫入與還原共用同一檢查。5,000 事件、32 帳戶、50,000 總行數與 16 MiB 可攜 payload 限制仍存在；行數或 bytes 可以先於事件數達滿。超限整筆回滾，原快照不變。舊版本可能拒絕超出其較小收據上限的寫入／匯入，不承諾降版使用。
