# 鎖定時取消確認窗與選單

範圍：M1-02／[RC-15](../architecture/architecture-baseline-v1.0-rc1.md#rc-15)及[隱私呈現](privacy-presentation.md)。修正 App 進入背景時仍開啟的確認窗、帳戶下拉與操作選單；不改金融資料模型。

## 問題與行為

原本鎖定只清除首頁內容，Navigator 上的浮層仍存在。捨棄草稿確認窗會蓋住鎖定畫面，帳戶下拉仍顯示名稱；若確認按鈕已按下、非同步回呼尚未繼續，舊確認結果也可能在鎖定開始後捨棄草稿。

App 現在共用追蹤 PopupRoute。鎖定時，首個畫面更新便把仍在顯示或退場中的浮層設為 offstage；尚未關閉的浮層直接取消，以空結果完成等待。追蹤保留至退場完成，避免正在淡出的選單仍顯示帳戶名稱。主頁路由維持，重新解鎖仍走原流程。

捨棄草稿確認記住開啟時的 view epoch，只有確認為真、畫面仍存在、epoch 未變且帳本仍解鎖，才會開始捨棄。若鎖定已開始，即使確認結果先前排入回呼，也不再使用它。正常保留／確認捨棄流程仍有原有測試。

已接受的草稿寫入仍依原規則完成並加密保存，再關閉工作階段；這項修正不反轉已完成的入帳或捨棄，不把畫面取消當資料庫回滾。沒有新增保存表、備份格式、金鑰、依賴套件或遠端請求。

## 驗證邊界

主機證據記錄修正前重現、修正後結果及相關舊畫面回歸；以實際結果為準。

新案例覆蓋開啟中的捨棄確認、已排隊確認、帳戶下拉及標籤選單。模擬 resumed → inactive → hidden → paused → hidden → inactive → resumed，核對第一個鎖定畫面沒有浮層內容、解鎖可操作、草稿身份／金額保留、帳本筆數與餘額不變，標籤未被誤封存。

Schema 7／snapshot 6／manual-entry-v1 不變；底層加密、程序中止、升級及五千筆資料沿用相同核心的 PR #51 證據，本批不重複執行或冒稱再次通過。Android debug 封裝與實機 gate 分開記錄；目前不操作手機，Recent Apps、實際生命週期與 TalkBack 仍待裝置驗收。
