# Data Exchange（M1-06，進行中）

已增加唯讀匯入預覽：使用者明確對應來源帳戶與目的帳戶後，先逐列檢查帳戶存在、目的工作空間、幣別、帳戶狀態及交易日期；任一列不符即回報來源列號，且不寫入帳本。預覽逐幣別分開統計收入與支出，使用 BigInt 避免整批總額超過單筆 Money 上限時溢位。預覽時的帳戶狀態只是快照，真正提交必須在同一資料庫交易內重新讀取並驗證，不能信任已開啟的預覽畫面。來源去重、原子寫入、文件介面與還原 gate 仍待完成。

此業務套件定義版本化的 `expensetracker-v2-simple-transactions` JSON／CSV 格式，先支援一般收入與支出。每筆保留來源工作空間、來源交易 ID、日期、帳戶 ID、交易類型、幣別與小數位、整數最小貨幣單位及備註。CSV 的備註欄位使用 JSON 字串，能往返逗號、引號、換行與非 ASCII 文字。來源 ID 重複、混合工作空間、錯誤日期／幣別／金額、未知欄位或版本、超過 5,000 筆或 24 MiB 都拒絕整份資料。

這是**待確認匯入的 staging 契約**，目前只有解析、產生與驗證；尚未寫入 Ledger、建立來源去重紀錄或提供 App 匯入／匯出 UI。不得以此宣稱 M1-06 完成。後續需先做帳戶對應、整批原子提交與永久去重，再接 Android 文件選取和可審查的確認畫面。轉帳、退款、撤銷、更正、刪除及分類／標籤／商家等完整歷史不在 v1 簡易交易格式中；完整可還原資料仍使用加密備份，不能把 CSV／JSON 當成備份。

格式中的金額使用十進位字串保存 `minorUnits`，不可經過浮點數。`sourceWorkspace + sourceRecordId` 預留為匯入去重身份，不能直接當目的帳本中的交易或 operation ID。解析不產生任何帳本寫入；實際匯入須重新走既有 Ledger use case 與 Audit。未來若擴充其他事件種類，需提高格式版本或定義明確可選欄位，不能讓舊讀取器默默遺失資料。
